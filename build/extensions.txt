# Agnostic core extension set — single source of truth for build/craft/*.yml.
# One extension name per line, blank lines and lines starting with # ignored.
#
# Deliberately the SAME list for every PHP branch this repo builds (7.4
# upward) — no per-branch conditional logic in build.yml. Extensions not
# bundled here are still available via `pvm ext` with its documented
# `--system` fallback for anything that needs a package manager
# (~/Projects/pvm CLAUDE.md section 10); musl static builds can't dlopen a
# .so anyway (section 8), so "compiled in or not at all" already applied.
#
# Excluded on purpose (tested empirically against PHP 7.4.33 in Alpine
# with this exact spc version before any of this was wired into CI):
#   - opcache: static compilation only supported by spc for PHP >= 8.0.
#   - intl: PHP 7.4's ext/intl C++ glue doesn't compile against the C++11
#     API the ICU version spc bundles today requires.
#   - dom, simplexml, soap, xml, xmlreader, xmlwriter (everything that
#     depends on the libxml pseudo-extension): PHP 7.4's ext/libxml.c calls
#     libxml2 functions that were renamed/changed signature upstream since
#     (e.g. php_libxml_output_buffer_create_filename, the
#     xmlSetStructuredErrorFunc callback signature).
# Keeping one list for every branch means 8.1+ loses these too, trading
# opcache/intl/XML support for zero version-specific branching in the
# pipeline — pvm's `ext --system` fallback is the intended escape hatch if
# a workload needs them.
#
# Names are as static-php-cli's `spc` expects them; verified against a real
# spc 2.8.5 binary (`spc dev:extensions`) before being added here.
